# Build and review a community release

Use Windows x64 with Node.js 24 LTS, npm, PowerShell and Git. These are build tools, not end-user prerequisites. Start from the provided source ZIP in a new directory. Do not build from a private operational profile. The selected source is controlled by the explicit `release-files.json` file allowlist. Changes require review and deliberate updates to that list; `.gitignore` alone is not the publication boundary.

1. Run `npm ci`, `npm ci --prefix desktop` and `npm ci --prefix desktop-runtime`.
2. Obtain the PostgreSQL Windows archive specified in `scripts/prepare-postgres-runtime.mjs` from its official URL. Place it at `.desktop-vendor/postgresql-16.14-2-windows-x64-binaries.zip` or set `NAUTEX_POSTGRES_ARCHIVE` to it. The preparation script checks its pinned SHA-256; an independent official download was verified for this candidate. Also obtain Microsoft's x64 redistributable from `https://aka.ms/vc14/vc_redist.x64.exe` as `.desktop-vendor/vc_redist.x64.exe`. `scripts/prepare-vc-runtime.ps1` verifies its pinned hash and Microsoft signature. If Microsoft changes the evergreen file, review the new version and deliberately update the pin; do not bypass verification.
3. Run `npm run release:build`. It collects dependency notices, scans and zips allowlisted corresponding source, generates brand assets, builds both frontends/backend, prepares database/migrations, writes standalone configuration and invokes NSIS with `--publish never`.
4. Run `npm run test:community` and the packaged acceptance harness: `node scripts/test-community-installed.mjs <absolute-executable-path> <new-absolute-test-directory>`. Never point that directory at an existing profile. The harness blocks external calls and supplies only synthetic data.
5. Unpack `resources/app.asar` with the installed `@electron/asar` library, then scan it and the complete resources tree with `node scripts/scan-release.mjs <directory>`. Also verify the nested source ZIP against its allowlist and hashes.
6. Copy `public/legal/source.zip` to `Nautex-AI-Source-0.3.14.zip` beside the installer. Hash the final assets with SHA-256. If code or docs change, regenerate corresponding source and rebuild the package before calling the artifacts matched.

The package reuses Electron's Node runtime for its backend, initialises PostgreSQL at an available loopback port and applies Prisma migrations. Data is outside installation resources. Quitting stops the managed backend and PostgreSQL. Existing recovery/upgrade code is retained. NSIS preserves the community profile on uninstall; deleting that profile is a separate, deliberate user operation. No migration from an owner's private Nautex profile is performed.

The community app ID is `org.oasisai.nautex.community`, executable/product name **Nautex AI**, application version `0.3.14`. The source-only publication tag is `v0.3.14-source.1`; the older local `v0.3.14` identifies an earlier candidate and is not this release. Unsigned packaging is the default because no signing credential was available to this isolated build. A publisher may add an authorised signing configuration and secrets in protected CI storage; never add them to the allowlist or source. Recalculate checksums after signing. Auto-updates are disabled until a trusted release feed is deliberately configured.

Prepare a fresh Git repository from this allowlist. Do not push the development repository or rewrite its private history. Inspect the intended public blobs, reuse prior scan evidence for unchanged inputs, review images, and confirm the asset manifest. Each GitHub Release asset must be below 2 GiB ([GitHub documentation](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)). The public repository at https://github.com/zpointai/nautex starts from a single sanitised snapshot; private history and local candidate tags are not published. Tag the exact source commit and never reuse or move an earlier release tag.

Source-only publication is separate from binary clearance. Before any installer or native-materials archive upload, resolve the documented per-component redistribution obligations and complete clean-Windows qualification. Regenerate matching source, installer, dependency materials, inventories and checksums after changes, and use a new unambiguous tag at the final source commit. Signing is optional; disclose unsigned status. These build scripts never push or upload automatically.

After packaging, run `node scripts/audit-native.mjs releases/win-unpacked releases/native-inventory`. Supply both generated inventory files and the separate native-materials ZIP beside the installer. Every native file must be classified; inventory success is not publication clearance. `scripts/test-native-runtime.mjs` checks actual Sharp image processing and the absence of retained wxWidgets imports during the build.

For the exhaustive installer review, extract its seven `$PLUGINSDIR/*.dll` files into an isolated directory and run `node scripts/audit-native.mjs <installed-root> <output-directory> <setup-exe> <plugin-extract-root>` before uninstalling. This includes the generated uninstaller and outer setup in the same per-file inventory.

The visible product name is **Nautex AI**. The existing internal application ID and `Nautex Community` data directory are intentionally retained for compatibility and separation from private installations. They are storage identifiers, not a separate product brand.
