# Module requirements — Nautex AI 0.3.14

Source audit, 4 October 2026. General AI means DeepSeek (`deepseek-flash` default/fast, `deepseek-v4-pro` reasoning) or Gemini (`gemini-3.1-pro-preview` default/reasoning, `gemini-3-flash-preview` fast). Users can change IDs in Settings. Live provider compatibility and task quality were not re-qualified using paid requests.

| Module | Without AI | AI functions / provider requirements | Other data/services | Unavailable state | Source evidence |
| --- | --- | --- | --- | --- | --- |
| Command Center | Metrics, record search, notifications and approvals from this workspace. | Ask Nautex language routing; individual AI actions. | User-created operational records; no catalogue required. | Empty metrics are zero. AI setup is optional. | components/nautex-erp-app.tsx; lib/command-center/metrics.ts |
| Purchase Orders | Create, edit, review and export orders; structured document parsing, receipts and delivery workflows. | Ambiguous document intake and order review. | Own suppliers and orders. Catalogue links are optional. | Manual entry and deterministic parsing remain available; AI escalation requires a provider. | lib/purchase-orders/intake-agent.ts; app/api/v1/purchase-orders |
| Suppliers | Directory CRUD, filters and deterministic matching. | Generated enrichment, expanded discovery and AI ranking. | Own supplier records. Web enrichment needs internet; Google Places separately needs its own server credential and billing. | Local records remain available. External/AI enrichment may be unavailable. | lib/matching; app/api/v1/suppliers |
| Agreements | Import, versions, comparison, pricing, customer contracts and rule-based enrichment. | No general-purpose AI call in the agreement routes; optional Jev advice uses a separate provider. | Own agreements; catalogue matching needs an authorised import. | No matches when catalogue is empty; agreement work remains available. | lib/agreements; app/api/v1/agreements |
| Backorders | Cases, escalation, status updates and deterministic email drafts. | Optional AI drafting. | Own orders; Microsoft 365 mailbox connection for mailbox actions. | Drafts are labelled as deterministic fallback when AI is unavailable; email integration is separate. | lib/backorders/email-draft.ts; app/api/v1/backorders |
| Fleet Tracking | Saved fleet/watchlist and cached snapshots; order links. | None for vessel lookup, map or tracking. | Live lookup uses public VesselFinder pages and internet; map tiles use external services. No paid AIS feed is bundled. | Cached data or explicit lookup errors; live data is not guaranteed and is not an AI requirement. | lib/vessel-provider.ts; components/vessel-tracking-panel.tsx |
| Inventory | Stock records, movements, reservations, warehouse receipts and reconciliation. | No provider needed for inventory operations. | Own stock; catalogue linking is optional. | Empty stock list; manual records remain available. | app/api/v1/inventory; lib/inventory |
| SLA Evidence | Upload and parse text/PDF/spreadsheet evidence, review, link orders and retain audit trail. | No general-purpose AI call in the evidence route. | Own evidence files and orders; text extraction is local, scanned-image OCR is not guaranteed. | Empty evidence list or unsupported-document error; no catalogue requirement. | lib/evidence/sla-evidence.ts; app/api/v1/evidence/route.ts |
| Finance | Invoices, settlements, matching, aging, exceptions and exports. | No provider needed for financial calculations or record workflows; optional Jev advice is separate. | Own financial records and configured company details. | Empty records and validation messages; AI is optional. | app/api/v1/finance; lib/finance |
| Item Search | Keyword/rule search over inventory, agreements, quotes, orders, RFQs and imported catalogue; history. | No embedding or semantic-search provider is implemented in this module. | User records or authorised catalogue data; no bundled search index. | No results when data is absent; unrelated records are still searchable. | lib/item-search/service.ts; app/api/v1/catalog/search/route.ts |
| IMPA Catalogue | Authorised CSV/XLSX import, code/description lookup, favourites and record links. | None for import, browsing or lookup. | User must independently obtain rights to catalogue data. No IMPA rows, images, index or embeddings are supplied. | Zero items and No catalogue imported, with empty schema template. | lib/datasets/impa.ts; components/modules/impa-search.tsx |
| HS Codes | History, favourites, authorised HS dataset import and dataset-backed classification where a match exists. | AI classification when no applicable local dataset match exists, and AI code verification, require DeepSeek or Gemini. | Own descriptions; optional authorised HS dataset. Suggestions require human customs review. | Without a matching HS dataset or provider, no classification is generated; inputs remain available. | app/api/v1/hs-code; lib/ai/services/hs-code.ts |
| RFQ Automation | Structured text/spreadsheet extraction, review/editing, persistence and deterministic supplier routing. | Unstructured RFQ extraction and enriched supplier routing. | Own RFQs and suppliers. Catalogue improves matching but is optional. | Explicit deterministic fallback; unsupported structured input returns an error instead of a simulated result. | app/api/v1/rfq/process/route.ts; lib/rfq/deterministic.ts |
| Validator | Deterministic document parsing, line comparison, persisted review and exceptions. | Agent-level procurement/order AI review is separate from this deterministic module. | Own quotes/orders or uploaded text documents; catalogue is optional. | Rule comparison remains available; unsupported documents show an error. | app/api/v1/procurement/validate/route.ts; lib/ai/services/procurement.ts |
| Price Calculator | Markup, margin, currency and totals calculations; authorised record context. | None. | User inputs; catalogue prices are not supplied. | Manual inputs work without keys or catalogue. | components/modules/price-calculator.tsx; app/api/v1/price-calculator/calculate/route.ts |
| Agent Monitor | Registry, run/task history, approvals, scheduling controls and audit. | Only actions that invoke the AI adapter require a provider; deterministic controls do not. | Workspace records; external services depend on the selected agent action. | No AI provider configured; controls and history stay available. Human approval rules still apply. | lib/agents/controls.ts; lib/agents/monitor.ts; lib/ai/engine/actions.ts |
| Exceptions | Review, assign and resolve operational exceptions. | No provider required for queue operations. | Own exception records. | Empty queue until records exist. | components/modules/exceptions-queue.tsx; app/api/v1/agents |
| Ask Nautex | Keyword routing to implemented actions and approval/history views. | Natural-language routing and individual AI actions require DeepSeek or Gemini. | Action-specific workspace records and permissions. | Keyword routing is deterministic; unsupported/unconfigured AI actions fail visibly, never simulate success. | lib/ai/engine/router.ts; lib/ai/engine/actions.ts |
| Settings / optional Jev advice | Company setup, local employee accounts, profiles, diagnostics and provider settings. | Optional Jev typed advice uses TypeSafe jev-1.13.0, separate from DeepSeek/Gemini. | Separate TypeSafe key, consent and daily limit; Microsoft 365 mailbox needs an Entra app/tenant and user authorisation. | Unconfigured integrations stay disabled. Jev is experimental; live compatibility is unverified. | lib/ai/jev-settings.ts; lib/ai/typesafe.ts; lib/mailbox/microsoft365.ts |

Qualification boundary: the retained four general-provider API identifiers were rechecked individually against official documentation. No live compatibility or quality claim is added. See [the budget-gated test](LIVE_PROVIDER_TEST.md) and [pending clean-Windows procedure](CLEAN_WINDOWS_TEST.md).
